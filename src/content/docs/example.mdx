import { FileTree } from '@astrojs/starlight/components';

Org marks `Jira Project Context` required. Team fills it with `PAY`. Repo adds local context. The vendored `SKILL.md` has no annotations or placeholder comments.

## Flow

```text
# /README.md
org SKILL.md -> team SKILL.md -> repo SKILL.md -> .claude/skills/sdlc/SKILL.md
```

## 1. Organization

The organization owns the base SDLC skill. It marks local sections as required and the security review as final.

```md
# /org/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Enterprise SDLC skill for Jira-driven code changes.
---

# Enterprise SDLC

## Read The Jira Issue

Use Jira integration to read the assigned issue. The Jira project is declared in the Jira Project Context section.

## Jira Project Context <!-- @required -->

<!-- Team must declare the Jira project key and any project-specific issue lookup rules. -->

## Implement

Use the issue acceptance criteria as the source of truth. Keep changes narrow.

## Team Implementation Guidelines <!-- @required -->

<!-- Team must add engineering guidance that applies across its repositories. -->

## Repository Context <!-- @required -->

<!-- Repository must add local ownership and verification guidance. -->

## Security Review <!-- @final -->

Review the diff for authentication, authorization, injection, secret exposure, and sensitive data handling risks.
```

## 2. Team

The payments team fills the Jira project context and team guidance.

```md
# /teams/payments/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Payments SDLC guidance.
---

## Jira Project Context

Use Jira project `PAY`.

## Team Implementation Guidelines

Prefer ledger-safe changes, preserve audit trails, and include migration notes for schema changes.
```

## 3. Repository

The repository declares source order and fills local context.

```yaml
# /repos/payments-api/skills.yaml
skills:
  enterprise-sdlc:
    sources:
      - ../../org/skills/sdlc/SKILL.md
      - ../../teams/payments/skills/sdlc/SKILL.md
      - .skills-src/sdlc/SKILL.md
    output: .claude/skills/sdlc/SKILL.md
    report: .skills/reports/enterprise-sdlc.json
    lock: skills.lock.yaml
```

```md
# /repos/payments-api/.skills-src/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Payments API SDLC guidance.
---

## Repository Context

Use this repository's CONTRIBUTING.md, CODEOWNERS, and local verification guidance before final response. Payment authorization code lives in `src/authz/`.
```

## Vendored Output

The vendored file is generated. Do not edit it directly.

```md
# /repos/payments-api/.claude/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Payments API SDLC guidance.
---

# Enterprise SDLC

## Read The Jira Issue

Use Jira integration to read the assigned issue. The Jira project is declared in the Jira Project Context section.

## Jira Project Context

Use Jira project `PAY`.

## Implement

Use the issue acceptance criteria as the source of truth. Keep changes narrow.

## Team Implementation Guidelines

Prefer ledger-safe changes, preserve audit trails, and include migration notes for schema changes.

## Repository Context

Use this repository's CONTRIBUTING.md, CODEOWNERS, and local verification guidance before final response. Payment authorization code lives in `src/authz/`.
```

The adoption point is narrow: a team starts with Markdown, adds a manifest, compiles to clean Markdown, and reviews the generated diff.
