This example uses Markdown as the source format. The compiler resolves the organization skill, applies the team and repository sections, verifies the contract, strips annotations, and writes vendored `SKILL.md`.

## 1. Organization

The organization owns the base SDLC skill. It marks the Jira project context, team implementation guidance, and repository context as required. It marks the security review as final.

```md
# /org/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Enterprise SDLC skill for Jira-driven code changes.
---

# Enterprise SDLC

## Read The Jira Issue

Use the Jira skill to read the assigned issue. The Jira project is declared in the Jira Project Context section.

## Jira Project Context <!-- @required -->

<!-- Team must declare the Jira project key and any project-specific issue lookup rules. -->

## Implement

Use the issue acceptance criteria as the source of truth. Keep changes narrow.

## Team Implementation Guidelines <!-- @required -->

<!-- Team must add engineering guidance that applies across its repositories. -->

## Repository Context <!-- @required -->

<!-- Repository must add local ownership and verification guidance. -->

## Security Review <!-- @final -->

Review the diff for authentication, authorization, injection, secret exposure, and sensitive data handling risks.
```

The organization contract says:

- `Jira Project Context` must be supplied before final output.
- `Team Implementation Guidelines` must be supplied before final output.
- `Repository Context` must be supplied before final output.
- `Security Review` cannot be replaced downstream.

## 2. Team

The payments team supplies the Jira project context and team implementation guidance. The heading text is the section identity.

```md
# /teams/payments/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Payments SDLC guidance.
---

## Jira Project Context

Use Jira project `PAY`.

## Team Implementation Guidelines

Prefer ledger-safe changes, preserve audit trails, and include migration notes for schema changes.
```

At this point the skill is still incomplete because the repository context is not present.

## 3. Repository

The repository supplies local operating context.

```md
# /repos/payments-api/.skills-src/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Payments API SDLC guidance.
---

## Repository Context

Use this repository's CONTRIBUTING.md, CODEOWNERS, and local verification guidance before final response. Payment authorization code lives in `src/authz/`.
```

## Vendored Output

The compiler strips annotations and comments, preserves organization-owned final prose, and writes clean Markdown for the agent.

```md
# /repos/payments-api/.claude/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Payments API SDLC guidance.
---

# Enterprise SDLC

## Read The Jira Issue

Use the Jira skill to read the assigned issue. The Jira project is declared in the Jira Project Context section.

## Jira Project Context

Use Jira project `PAY`.

## Implement

Use the issue acceptance criteria as the source of truth. Keep changes narrow.

## Team Implementation Guidelines

Prefer ledger-safe changes, preserve audit trails, and include migration notes for schema changes.

## Repository Context

Use this repository's CONTRIBUTING.md, CODEOWNERS, and local verification guidance before final response. Payment authorization code lives in `src/authz/`.

## Security Review

Review the diff for authentication, authorization, injection, secret exposure, and sensitive data handling risks.
```

The important point is the adoption curve: a team starts with Markdown, not a new resource format. The rigor comes from compiler checks around required sections, final sections, duplicate headings, and the generated merge report.
