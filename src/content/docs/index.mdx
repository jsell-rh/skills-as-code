Agent skills are Markdown files. That is the starting point.

Those Markdown files are becoming supply-chain inputs. They steer tool use, shell commands, file edits, code review, and run reporting. A loose folder of prose can work for an individual developer. It does not give an enterprise enough control over inheritance, review, versioning, or provenance.

**Skills as Code** is a proposed open pattern for declaratively managing prose-based skills without requiring a new agent runtime.

<div class="statement-panel">
  <p><strong>The core idea:</strong> treat <code>SKILL.md</code> as a compiled artifact. Author structured Markdown source, inherit it with Kustomize, verify the rendered result with policy, emit ordinary <code>SKILL.md</code>, and record the lineage in an AIBOM.</p>
</div>

## Why It Matters

Current skill systems make authoring easy. Enterprises need control:

<CardGrid>
  <Card title="Inheritance without forks">
    A platform team publishes base skill prose. Product teams overlay approved sections instead of copying and drifting.
  </Card>
  <Card title="Policy before runtime">
    Locked prose blocks, command patterns, patch paths, and source refs are checked before an agent can load the rendered skill.
  </Card>
  <Card title="Current-agent compatibility">
    The final output is a normal `SKILL.md`. The build path adds rigor; the agent still consumes prose.
  </Card>
  <Card title="AIBOM by default">
    Every run can report which skill, ancestor, overlay, digest, check, and compiled artifact influenced the work.
  </Card>
</CardGrid>

## The Minimal Flow

This is the whole pattern for a prose-based enterprise SDLC skill.

```text
# /README.md
Markdown source -> Kustomize overlay -> policy check -> SKILL.md -> AIBOM
```

### Base

The base is not a workflow DSL. It is a Kustomize-compatible YAML envelope around Markdown content.

The envelope exists so teams can patch and verify prose structurally. The rendered output remains `SKILL.md`.

```yaml
# /skills/sdlc/base/skill.yaml
apiVersion: skills.agent.dev/v1alpha1
kind: Skill
metadata:
  name: enterprise-sdlc
spec:
  description: Enterprise SDLC guidance for agentic code changes.
  target: SKILL.md
  contract:
    lockedBlocks: [security-review, run-record]
    allowedPatchPaths:
      - /spec/blocks/2/markdown
    allowedCommandPatterns:
      - npm test
      - make test-*
  blocks:
    - id: purpose
      markdown: |
        # Enterprise SDLC

        Use this skill when making code changes in an enterprise repository.

    - id: planning
      markdown: |
        ## Planning

        Before editing files, write a short plan.

    - id: testing
      markdown: |
        ## Testing

        Run `npm test` after modifying code.

    - id: security-review
      markdown: |
        ## Security Review

        Review the diff for authentication, authorization, injection,
        secret exposure, and sensitive data handling risks.

    - id: run-record
      markdown: |
        ## Run Record

        Record the activated skill name, digest, commands run,
        files changed, verification result, and unresolved risks.
```

### Overlay

The team overlay is native Kustomize. It changes only the testing block.

```yaml
# /skills/sdlc/payments/kustomization.yaml
resources:
  - github.com/acme/agent-skills//sdlc/base?ref=2f4c6c0f93c5a2c39a6b8c3e5f4a1a8e9c7d6b50

namePrefix: payments-

patches:
  - path: patch-testing.yaml
    target:
      group: skills.agent.dev
      version: v1alpha1
      kind: Skill
      name: enterprise-sdlc
```

```yaml
# /skills/sdlc/payments/patch-testing.yaml
- op: replace
  path: /spec/blocks/2/markdown
  value: |
    ## Testing

    Run `make test-payments` after modifying payment service code.
```

### Check

Verification runs on the rendered Markdown source before compilation.

```bash
# /scripts/build-skill.sh
kustomize build skills/sdlc/payments > build/rendered/payments-sdlc.yaml
skillc verify --policy policies/enterprise-sdlc.yaml build/rendered/payments-sdlc.yaml
skillc compile --out build/skills build/rendered/payments-sdlc.yaml
```

The verifier rejects illegal edits before the agent sees the skill.

```yaml
# /policies/enterprise-sdlc.yaml
apiVersion: skills.agent.dev/v1alpha1
kind: SkillPolicy
metadata:
  name: enterprise-sdlc-policy
spec:
  requireImmutableRemoteRefs: true
  requiredLockedBlocks: [security-review, run-record]
  allowedMarkdownCommandPatterns: [npm test, make test-*]
  denyMarkdownCommandPatterns: ["git push", "rm -rf"]
  requireAibom: true
```

### Output

The compiled output is ordinary Markdown.

```md
<!-- /build/skills/payments-sdlc/SKILL.md -->
---
name: payments-enterprise-sdlc
description: Enterprise SDLC guidance for agentic code changes.
metadata:
  sourceDigest: sha256:8b1a...
  resolvedFrom:
    - enterprise-sdlc@sha256:4e2d...
    - payments-overlay@sha256:91ac...
---

# Enterprise SDLC

Use this skill when making code changes in an enterprise repository.

## Testing

Run `make test-payments` after modifying payment service code.
```

### AIBOM

The run record links the activated skill back to the base, overlay, compiled digest, and verification checks.

```jsonc
// /runs/PAY-1842/aibom.json
{
  "resolvedSkills": [
    {
      "name": "enterprise-sdlc",
      "relationship": "base",
      "digest": "sha256:4e2d..."
    },
    {
      "name": "payments-enterprise-sdlc",
      "relationship": "overlay",
      "digest": "sha256:91ac..."
    },
    {
      "name": "payments-enterprise-sdlc",
      "relationship": "compiled-skill",
      "digest": "sha256:8b1a..."
    }
  ],
  "activatedSkills": [
    {
      "name": "payments-enterprise-sdlc",
      "digest": "sha256:8b1a..."
    }

  ]

```

## What This Is Not

This is not another agent framework. It is not a workflow engine. It is not a new runtime semantics layer for skills.

It is a supply-chain layer for the skill format teams already use: Markdown source, deterministic render, policy verification, compiled `SKILL.md`, and provenance.

## Design Principles

<CardGrid>
  <Card title="Start with prose">
    Skills are Markdown today. The first version should manage prose safely, not assume a future executor.
  </Card>
  <Card title="Boring by design">
    Reuse Kustomize, JSON Patch, CI checks, digests, and BOM conventions.
  </Card>
  <Card title="Flat at the edge">
    Agents consume compiled `SKILL.md`. Humans and automation review structured Markdown source.
  </Card>
  <Card title="Provenance is not optional">
    A run that cannot identify its skill inputs, overlays, and checks is not production-grade.
  </Card>
</CardGrid>
