Skills are Markdown files today. The lowest-friction enterprise pattern should not ask teams to abandon that.

**Skills as Code** treats Markdown as the authoring format. A compiler reads ordinary `SKILL.md` files, applies a small contract language, verifies required and locked sections, and vendors clean `SKILL.md` output for the agent.

## The Shape

Three levels are enough for the minimum viable enterprise story:

<CardGrid>
  <Card title="1. Organization">
    Publishes the base SDLC skill, including required team/repo sections and the final security review.
  </Card>
  <Card title="2. Team">
    Supplies the Jira project context and team implementation guidance as Markdown sections.
  </Card>
  <Card title="3. Repository">
    Supplies local ownership and verification context.
  </Card>
  <Card title="Vendored Output">
    The agent sees clean Markdown with contract annotations stripped.
  </Card>
</CardGrid>

## The Example

The organization publishes a generic SDLC skill as Markdown:

```md
# /org/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Enterprise SDLC skill for Jira-driven code changes.
---

# Enterprise SDLC

## Read The Jira Issue

Use the Jira skill to read the assigned issue. The Jira project is declared in the Jira Project Context section.

## Jira Project Context <!-- @required -->

<!-- Team must declare the Jira project key and any project-specific issue lookup rules. -->

## Implement

Use the issue acceptance criteria as the source of truth. Keep changes narrow.

## Team Implementation Guidelines <!-- @required -->

<!-- Team must add engineering guidance that applies across its repositories. -->

## Repository Context <!-- @required -->

<!-- Repository must add local ownership and verification guidance. -->

## Security Review <!-- @final -->

Review the diff for authentication, authorization, injection, secret exposure, and sensitive data handling risks.
```

The team supplies the sections it owns:

```md
# /teams/payments/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Payments SDLC guidance.
---

## Jira Project Context

Use Jira project `PAY`.

## Team Implementation Guidelines

Prefer ledger-safe changes, preserve audit trails, and include migration notes for schema changes.
```

The repository supplies local context:

```md
# /repos/payments-api/.skills-src/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Payments API SDLC guidance.
---

## Repository Context

Use this repository's CONTRIBUTING.md, CODEOWNERS, and local verification guidance before final response. Payment authorization code lives in `src/authz/`.
```

The compiled result is ordinary Markdown:

```md
# /repos/payments-api/.claude/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Payments API SDLC guidance.
---

# Enterprise SDLC

## Read The Jira Issue

Use the Jira skill to read the assigned issue. The Jira project is declared in the Jira Project Context section.

## Jira Project Context

Use Jira project `PAY`.

## Implement

Use the issue acceptance criteria as the source of truth. Keep changes narrow.

## Team Implementation Guidelines

Prefer ledger-safe changes, preserve audit trails, and include migration notes for schema changes.

## Repository Context

Use this repository's CONTRIBUTING.md, CODEOWNERS, and local verification guidance before final response. Payment authorization code lives in `src/authz/`.

## Security Review

Review the diff for authentication, authorization, injection, secret exposure, and sensitive data handling risks.
```

## What Matters

- Authors keep writing Markdown.
- Required sections make the base skill intentionally incomplete until a team or repository supplies local prose.
- Final sections protect organization-owned instructions from downstream edits.
- Vendored output makes review and CI drift detection straightforward.
