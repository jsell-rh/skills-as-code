Skills are Markdown files today. The first problem to solve is not a new skill runtime. It is how organizations manage shared skill prose without copy-paste drift.

**Skills as Code** treats `SKILL.md` as a compiled artifact. Teams author structured Markdown source, inherit it with Kustomize, and compile the resolved result back to ordinary `SKILL.md`.

## The Shape

Three levels are enough for the minimum viable enterprise story:

<CardGrid>
  <Card title="1. Organization">
    Owns the base SDLC skill, the Jira intake pattern, the implementation scaffold, and the locked security review.
  </Card>
  <Card title="2. Team">
    Adds the required Jira project context and team implementation guidance.
  </Card>
  <Card title="3. Repository">
    Adds repository-specific ownership and local operating context.
  </Card>
  <Card title="Compiled Skill">
    The agent still sees a normal `SKILL.md`.
  </Card>
</CardGrid>

## The Example

The organization publishes a generic SDLC skill:

```yaml
# /org/skills/sdlc/skill.yaml
apiVersion: skills.agent.dev/v1alpha1
kind: Skill
metadata:
  name: enterprise-sdlc
spec:
  target: SKILL.md
  contract:
    requiredBlocks:
      - jira-project-context
      - team-implementation-guidelines
      - repo-context
    lockedBlocks:
      - security-review
    allowedPatchPaths:
      - /spec/blocks/jira-project-context
      - /spec/blocks/team-implementation-guidelines
      - /spec/blocks/repo-context
```

The team selects its Jira project using prose and adds implementation guidance:

```yaml
# /teams/payments/skills/sdlc/patch.yaml
- op: add
  path: /spec/blocks/jira-project-context
  value:
    order: 20
    markdown: |
      ## Jira Project Context

      Use Jira project `PAY`.
- op: add
  path: /spec/blocks/team-implementation-guidelines
  value:
    order: 40
    markdown: |
      ## Payments Team Guidelines

      Prefer ledger-safe changes, preserve audit trails, and include migration notes for schema changes.
```

The repository adds local context:

```yaml
# /repos/payments-api/.agents/skills/sdlc/patch.yaml
- op: add
  path: /spec/blocks/repo-context
  value:
    order: 50
    markdown: |
      ## Repository Context

      Use this repository's CONTRIBUTING.md, CODEOWNERS, and local verification guidance before final response. Payment authorization code lives in `src/authz/`.
```

The compiled result is plain Markdown:

```md
# /repos/payments-api/.agents/skills/sdlc/SKILL.md
---
name: enterprise-sdlc
description: Enterprise SDLC skill for Jira-driven code changes.
---

# Enterprise SDLC

## Read The Jira Issue

Use the Jira skill to read the assigned issue. The Jira project is declared in the Jira Project Context section.

## Jira Project Context

Use Jira project `PAY`.

## Implement

Use the issue acceptance criteria as the source of truth. Keep changes narrow.

## Payments Team Guidelines

Prefer ledger-safe changes, preserve audit trails, and include migration notes for schema changes.

## Repository Context

Use this repository's CONTRIBUTING.md, CODEOWNERS, and local verification guidance before final response. Payment authorization code lives in `src/authz/`.

## Security Review

Review the diff for authentication, authorization, injection, secret exposure, and sensitive data handling risks. This block is owned by the organization and cannot be changed by team or repository overlays.
```

## What Matters

- The organization can require Jira project context without hard-coding every team.
- The team can add guidance without forking the organization skill.
- The repository can add local context without weakening team or organization rules.
- The security review block is inherited by every downstream skill and cannot be changed outside the organization layer.
